## 1. Purpose
This contract defines exactly how a window of events becomes a feature row, so that offline training (M2) and online scoring
(M3) compute the same numbers. Any difference is training/serving skew.

## 2. Windowing
| Item | Definition |
|---|---|
| Event time | C-01 `timestamp` (epoch ms, emission time) |
| Windows | Sliding, length **30 s**, slide **10 s**, aligned to the Unix epoch. An event at *t* belongs to the 3 windows starting at `floor(t/10s)·10s − k·10s`, k ∈ {0,1,2}, each covering `[start, start+30s)`. This is identical to Spark `window(ts, "30 seconds", "10 seconds")` |
| Watermark | 60 s. Events later than this may be dropped online. The golden input has one late event (47 s) that **must** be included |
| Group key | (`window_start`, `window_end`, `src_ip`) |
| Online output mode | **Update** (D-01): a window row is re-emitted whenever it changes. The final value equals the golden value |

## 3. Columns (order = `GOLDEN_COLUMNS`)

| Column | Type | Definition |
|---|---|---|
| `window_start`, `window_end` | int (epoch ms) | Window bounds (`end = start + 30000`) |
| `src_ip` | string | Group key |
| `total_bytes` | int | Σ `bytes_sent` |
| `unique_ports` | int | Exact count of distinct `dst_port`. Spark streaming: `size(collect_set(dst_port))`, because `countDistinct` is not supported on streams |
| `syn_ack_ratio` | float | Σ `syn_flag` / (Σ `ack_flag` + 1) |
| `packet_rate` | float | `event_count / 30` (flows per second) |
| `bytes_per_flow` | float | `total_bytes / event_count` (0.2.0) |
| `port_ratio` | float | `unique_ports / event_count`. 1.0 = every flow hits a new port (scan signature) (0.2.0) |
| `syn_share` | float | Σ `syn_flag` / `event_count` (0.2.0) |
| `event_count` | int | Number of events (auxiliary, not a model input) |
| `max_event_ts` | int (epoch ms) | Max `timestamp` in the window (auxiliary, used for latency in C-05) |
| `label_attack` | bool | **Eval-only.** True if any event has `label ≠ "BENIGN"` |
| `label_type` | string | **Eval-only.** The most frequent non-benign label (ties broken alphabetically), else `"BENIGN"` |

**Model input order (0.2.0, ADR-012):** `[bytes_per_flow, port_ratio, syn_ack_ratio, syn_share]` (`FEATURE_ORDER`).
`BASE_FEATURES` = `[total_bytes, unique_ports, syn_ack_ratio, packet_rate]` (stored in C-04). `RULE_FEATURES` = base + ratios
(what C-03 rules may reference).
Eval-only columns are never model inputs (Art. VII). C-01 `SCORING_FIELDS` lists the only event fields that features read.

## 4. Offline timing (ADR-011)
To train on windows that match replay, M2 assigns replay timestamps `ts_i = t0 + floor(i·1000/R_ref)` ms (R_ref = 5000 ev/s, so 5 rows per ms; `ids_contracts.features.replay_timestamp`) over the replay
dataset in day order, then `row_idx` order (C-01 §4.4), with `t0` a multiple of 10 s. It then applies §2–§3 unchanged.

## 5. Validation
- `read_feature_csv(path)` reads the golden format. `validate_feature_row(row)` checks types, alignment and internal consistency.
- `rows_equal(a, b)` is the comparison: exact for ints, strings and bools, and 1e-9 absolute for floats.
- **Golden parity:** the M2 pandas implementation and the M3 Spark job, given `events_golden.jsonl`, must each produce exactly the 23 rows of
  `features_golden.csv` (sorted by `window_start`, `src_ip`).
